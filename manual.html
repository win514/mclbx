mclbx 联机工具

版本 mclbx 1.48 平台 Windows 10 / 11（64 位） 形态 单个 exe，无需安装 网络 除域名入口外全程可离线部署

1 这个工具做什么

Minecraft Java 版的联机要求建立一条从玩家到房主游戏进程的通道。家庭网络通常处在 NAT 之后、并且没有可用的公网地址，通道因此建不起来。本工具提供三种打通方式，并负责把它们之间的选择与切换自动化。

同一个局域网内不需要本工具：原版「对局域网开放」会向局域网广播，同一网段的玩家在「多人游戏」列表里直接就能看到这个房间。本工具处理的是局域网之外的情况。

入口玩家需要做什么适用条件
公网入口 游戏内「多人游戏 → 直接连接」填入地址 房主有可被外部访问的地址（公网 IPv6，或自动端口映射成功）
软件入口 安装本工具后填入房主给的链接或房间码 双方网络都不理想时；已配置中继服务器则直连失败会自动改用中继
中继转发 同上，或使用中继提供的地址 要求公网 IPv6 与自动端口映射都不可用时的兜底方案

它不做什么

  • 不支持基岩版（Bedrock）。只支持 Minecraft Java 版：基岩版是另一套协议，走 UDP，端口（默认 19132）、握手与加密均与本工具承载的 TCP 协议不同。
  • 不修改游戏本体，不注入进程，不要求安装 mod 或联机插件。
  • 不修改注册表，不改动网卡、路由表和 DNS 设置。
  • 除「入站规则」这一项外，不改动系统防火墙；该操作需由用户主动执行。
  • 不收集、不上传任何数据；界面服务只监听本机。

2 连接方式怎么选

先做一次体检（打开界面会自动执行），再按结论选路线。下表为判读与对应选择的完整映射。

体检结论推荐做法说明
公网 IPv6 可用 公网入口（IPv6） 最省事：玩家不需要安装，地址短、无需中继。同时要求玩家一侧具备 IPv6 出口。
IPv6 不可用，自动端口映射可用 创建房间 / 直连模式（房主） 映射成功后把地址直接发给玩家。映射依赖路由器开启 UPnP 或 NAT-PMP / PCP。
两者都不可用（含对称型 NAT） 中继转发（房主）+ 中继转发（玩家），或本机中继 此时打洞成功率极低，建议直接使用中继。
结论不稳定或抓不到 关闭「跳过自动端口映射探测」后重新体检 该选项跳过映射探测以加快检测，代价是结论更保守。
关于中继：中继转发会让流量经过第三方机器。自建方式有两种：在具备公网地址的机器上运行「公网中继」，或在自己的机器上运行「本机中继」并由对方填入它输出的链接。中继地址在「高级选项 → 中继服务器」中填写，该栏留空表示不使用中继，此时直连失败不会自动切换，会直接中断并说明原因。

3 快速开始

界面默认只呈现两个入口：创建房间（房主）与加入房间（玩家）。其余 20 项操作常驻在左侧栏里，按用途分组并带搜索，随时可点。

房主：两步创建房间

  1. 在游戏内开启局域网进入世界后按 Esc → 对局域网开放，记录显示的端口号（通常为 25565）。世界未开启时，工具没有可转发的端口。
  2. 创建房间并发送邀请房间码留空时自动生成；端口填写上一步记录的端口号，点击「创建房间」。地址生成后点击「复制邀请」，将邀请文本整段发送给玩家。

玩家：两步加入房间

  1. 未安装本工具在游戏内「多人游戏 → 直接连接」中粘贴房主提供的地址并回车。如有需要，请房主将玩家名称加入白名单。
  2. 已安装本工具点击「加入房间」，粘贴房主提供的邀请文本，点击「连接」。地址与房间码会自动提取；已配置中继服务器时，直连失败会自动改用中继。
环境检测无需手动触发：界面打开时会自动执行一次，执行期间左上角显示「检测中…」，完成后替换为四项指标。需要重新执行时点击左上角「重新检测」。

4 体检结论怎么读

体检给出四项结论，界面顶部的能力条会同步显示。不支持的连接方式会被自动置灰，鼠标悬浮在置灰项上会说明原因，不需要自己去日志里判断。

结论项含义与影响
公网 IPv6 本机是否具备可被外部直接访问的 IPv6 地址。可用即可以最省事的方式联机。
NAT 类型 分为全锥形、受限锥形、端口受限锥形、对称型与未知。锥形越开放越容易打洞；对称型（移动网络与企业网络常见）几乎无法打洞，应直接使用中继。
自动端口映射 路由器是否响应 UPnP、NAT-PMP 或 PCP。三者任一可用即可自动开端口，无需进路由器后台。
游戏端口 默认 25565 是否空闲。被占用时换端口或先关闭占用程序，再由体检复检。

5 常见故障对照表

按症状检索即可，不必从头排查。

症状处理
玩家连接超时 确认地址与端口在两端一致；再看体检的自动端口映射是否可用，不可用则改用中继转发。
房主自测正常，玩家就是连不上 多数是入站被拦截。界面顶部出现「尚未放行入站」提示时点「放行入站」；也可手动执行「入站规则」。
域名入口玩家连不上 用「地址校验」按真实客户端的顺序逐步骤定位失败点。
UDP 被网络限制 改用「中继转发（房主）」与「中继转发（玩家）」，这条通道走 TCP。
双方都是对称型 NAT 不要尝试打洞，直接用中继；确需尝试时可用「端口探测」。
端口 25565 被占用 体检会报告该端口占用情况；更换端口后重新执行对应操作。
玩家中途掉线 不需要重新加入：断线约 30 秒后本工具会自动重连，游戏内填的地址在重连前后一直有效。重连期间的连接会被明确拒绝并记一行日志，网络恢复后即可继续。
未安装工具的玩家能进，装了工具的反而不行 两条入口用的端口不同：公网入口走游戏端口，软件入口还要一个信令端口（默认 8090）。后者的入站放行与端口映射要单独覆盖；界面上的「放行入站」会一次把两个端口都放行，命令行开房时卡片末尾也会印出该放行的端口。体检会单独探一次 IPv6 出口；若报「出口探测无应答」，先在浏览器打开纯 IPv6 网站确认本机能出去，或改用中继转发。
开着的房间突然连不上了 多数是地址变了：家用宽带的前缀被运营商重编、路由器重新拨号，或端口映射续约时换了外网端口。程序每 60 秒比一次公网 IPv6，变了会刷新界面上的地址与邀请文本；但已经发出去的那份邀请不会自己更新，请重新复制一次发给还没进来的玩家。正在游戏里的玩家不受影响。
玩家说连不上，但错误里写的是房主有问题 玩家侧的失败结论会同时提示「也可能是本机这一侧：延迟大 / 丢包 / UDP 被限制」。两端各查一次：玩家点「路况诊断」看本机的 NAT 类型与出口，房主看日志里有没有「信箱满了」或「短时间内有 N 位新玩家在登记」。300 ms 还丢包、或 UDP 被运营商限制的链路，直连本来就不成立，用中继。
自己也开着世界，再点「加入房间」 两者都要占本机的 25565。在「加入房间」里把「本机监听端口」改成别的（例如 25566）即可；游戏内仍是照常连房主。
白名单填了名字，结果谁都被拒 Java 版的玩家名只含英文、数字与下划线，填中文名永远匹配不上。程序在解析时会给一句提醒，照着改成玩家的英文 ID 即可。
开了中继转发给朋友，流量算谁的 算你的：朋友的数据先进你的机器、再经隧道发给房主，所以你的上行与下行都会被占用（按量计费时留意）。这个入口默认不校验玩家名，可以填「中继转发入口白名单」限定范围。
界面记住了错误的输入 在「设置 → 辅助工具」里点「清除」（只清填过的值，外观设置保留）；想连设置一起清掉，执行 mclbx forget。
需要把排查结果交给他人 日志区可「复制」全部输出；原始调试信息在折叠面板内，展开后一并复制。

共 20 项、6 个分组。字段提示与操作说明均由程序定义，改版时以界面显示为准。

7 界面说明

界面是三页一体的工具窗口：顶栏导航在工作台、设置、说明书三页之间切换，地址栏跟着走，刷新后还停在原页，浏览器后退也能退回上一步。

区域用途
顶栏四段：身份（这是哪个工具）、页面导航、链路条（本机 → 入口 → 房间 → 玩家）、状态胶囊（空闲 / 执行中 / 已结束）。
快速开始主区顶部「快速开始」：创建房间 / 加入房间。点击后表单就地展开，填写完成即执行，无需先去左侧选择操作。
链路条显示「本机 → 入口 → 房间 → 玩家」四段的连通状态。窗口变窄时它是第一个让位的（同样的信息在状态胶囊里也有一份）。
状态空闲、执行中的操作与已运行时长、执行结果。
本机环境侧栏第一块。未检测时为单格，显示「未检测 · 点击开始」，点击即开始检测；完成后替换为四项指标，不可用的能力标红。
操作侧栏第二块，常驻。按用途分组列出全部 20 项操作，带搜索框与「重新检测」。选中的操作，表单显示在主区「快速开始」下方。
提示条仅在检测到需要处理的问题时出现，一句话给出结论与一个可执行动作；点击「忽略」后本轮不再提示。
邀请段房间创建完成后出现，将地址、房间码、未安装工具的连接方式、已安装工具的命令合并为一段文本，配一个复制按钮，整段转发即可。
在场玩家创建房间后出现，列出已经通过身份校验的玩家：每人一行，显示安全码、连接方式与已连时长。安全码与玩家屏幕上显示的一致，念一遍核对即可确认没有中间人。只在有人真正进场后出现，重连时自动更新。
结论日志只输出结论、说明与建议，供普通使用者判断状态。
原始输出默认折叠，收纳 STUN 逐台应答、映射尝试、端口探测等原始信息，供排查使用。
命令选中操作后，表单右上角的「命令」显示界面将要执行的等价命令行，便于核对与转抄。
状态栏窗口最下面一条：本次操作的名字、最近一次写盘的保存状态、背景音乐入口、快捷键提示，以及停止与退出。
设置（一页）顶栏第二个导航项。主题外观：主题、强调色、材质、圆角大小、背景光效、背景图片、毛玻璃、面板淡入、界面字号、动画效果、侧边栏样式。辅助工具：背景音乐与填表与日志。关于与状态：只读信息（版本、环境、目录、占用）与设置变更记录。最后一块是维护动作（恢复默认、导出、导入、打开目录、复制版本、诊断包）。改完即生效，不需要重启，页里也没有「保存」按钮。
说明书（一页）顶栏第三个导航项。整页嵌入这份文档，主题跟着界面走；离开时点顶栏「工作台」即可。
界面会记住上次填写的参数（可在「设置 → 辅助工具」里关掉）。停止只结束当前任务，关窗与退出会结束任务并关闭程序；窗口消失先于收尾动作，因此关闭没有可感知延迟。

主题与外观

  • 主题：跟随系统 / 深色 / 浅色 / 高对比。浅色与高对比都只换底色与字色，版式、按钮位置与操作顺序一概不变。「跟随系统」跟随 Windows 的浅色/深色设置，系统改了它也跟着改。
  • 高对比：给「看不清」而不是「不喜欢」的场合用 —— 低端屏幕、白天靠窗的反光、投屏给旁边的人看。它把文字对比度推到很高的水平（正文约 20:1），并把背景的装饰渐变与网格关掉：装饰与「看清」在这类场合是冲突的。
  • 强调色：信号绿（默认）、蓝、紫。它决定「链路通到哪一段」这类状态用的颜色；警告与错误始终是琥珀与红，不随强调色变。
  • 材质「扁平」：去掉圆角、外阴影、渐变与光晕，只留颜色与 1px 线条。它和主题是两件事：主题换的是配色，材质换的是层次 —— 做成主题会得到「配色 × 材质」的组合爆炸，而名字里读不出「扁平」，所以它是一个独立开关。它是纯减法，绘制只会更省；焦点框会换成描边，键盘操作一样看得见。
  • 毛玻璃：面板半透明，并实时模糊背后的内容。强度是一个 0 到 10 的数值：数值越大，面板越透明、模糊也越强；0 表示关闭（面板实心、不做模糊）。默认从最低一档起步 —— 想要更明显的观感自己往上拉，随之而来的开销也更大。模糊按层次分配，不是每块面都一样糊：主容器（顶栏、状态栏、主区面板、设置页外壳）用一档，浮层（操作详情）用更强的一档，目标是"主次分明"而不是"越糊越好"；面板内部的次级卡片（操作行、环境格、日志面）只做半透明、不加模糊 —— 两层模糊相加看到的是糊，既贵又脏。侧栏与日志区刻意不在模糊范围内：它们的内容随搜索、追加与滚动一直在变。任务执行期间毛玻璃整体让位，跑完立刻恢复。它可以和背景图片一起用：设了背景图时，程序会把照片压得更暗一些，并给面板补一点不透明度，保证照片上的字仍然读得清（对比度门槛 4.5）。高对比主题不参与毛玻璃 —— 那一档的存在理由是"看清"，三块面始终接近实心。同一组里那行「帧率实测」可以在当前档位就地量一秒，低于 45 帧就说明这一档对你的机器偏重；想逐档对比又不想改设置：地址栏加 ?vfx=0 到 ?vfx=10 即可（老的 ?vfx=off / ?vfx=low / ?vfx=mid / ?vfx=high 这类写法仍然认），刷新即恢复你自己的设置。
  • 视觉美化（常开）：面板的半透明与模糊、轮廓微光、面板淡入合起来是同一层「装饰层」，它不再有总开关。实测这一层对帧率没有可测影响（见「资源占用」一节），关掉它省不下什么，却要多维护一处状态；真正能省的地方是毛玻璃档位，往下调即可见效。装饰层只影响观感：工具的功能、输入输出与计算逻辑与它无关。
  • 科幻轮廓微光：面板描边与四角的静态光晕，画好一次就不再重绘 —— 给阴影挂过渡等于每次过渡都逐帧重新光栅化。这一项已并入装饰层，不再单独开关。
  • 面板淡入：浮层出现时淡入，只动透明度、不动位置：玻璃面板一旦位移，背后那块模糊就得每帧重新采样。选「动效：精简」或系统开了「减少动态效果」时，它自动不生效。
  • 背景光效：极光与网格两层装饰渐变。关掉它不影响背景图片 —— 两者各自独立。
  • 背景音乐：曲库就是存档目录里的 music 文件夹，把音乐文件放进去（支持 MP3 / WAV / FLAC / M4A / OGG），点「刷新」即可。播放顺序可选顺序或随机（随机不会连续两首抽到同一首），循环可选不循环 / 列表循环 / 单曲循环，音量 0 到 100。底栏那个 ♪ 能播放与暂停，不用每次打开设置；默认不自动播放 —— 这是个会长时间开着的工具，不该在没人点的时候出声。播放不额外占 CPU：音频由界面内核直接解码，关掉窗口就停。只把真正的音频算进曲库（按扩展名与文件头两层判断），某个文件放不了会明说并跳到下一首，不会静默跳过。
  • 背景图片：点「导入图片…」选一张图（JPEG / PNG / GIF，单张上限 32MB），程序把它复制进存档的 wallpapers 目录并立刻用上；也可以直接把图丢进那个目录再点「刷新」。导入之后原文件改名、移走、删掉都不影响，整个存档文件夹拷到别的机器上背景图也还在。图片按比例铺满窗口（裁切，不拉伸变形），上面压一层与当前主题同色的暗化层，保证任意一张照片上文字仍读得清。程序会先把图缩到长边 2560 再显示，所以放一张 4K 图也不会拖慢界面；缩放结果缓存在数据目录的 ui-cache 下，源文件没变就不会重做。填了它，毛玻璃依旧生效（见上一条）；照片会被压得更暗一些，以保住照片上文字的对比度。
  • 动效「精简」：去掉所有过渡，以及「执行中」那个点的呼吸动画（点本身还在，只是不闪）；背景光效由它自己的开关控制，两者互不影响。系统设置里的「减少动态效果」始终优先，与这个开关是同一套规则。
  • 界面字号「大」：只把字放大一号（顶栏与状态栏的高度跟着走），控件位置与版式都不动。它和主题是两件事：主题解决"颜色读不读得清"，字号解决"字够不够大" —— 高对比能帮到前者，帮不到后者。默认是「标准」，需要的人自己去打开。
  • 默认中转服务器：填一次，所有带「中转服务器」字段的操作都会默认带上；某个操作想用别的，在它自己的字段里填即可（填过的优先）。默认游戏端口同理。
  • 原生界面（--native）不使用主题：它用系统控件，存在的理由就是省内存，因此保持系统外观。但「默认游戏端口」与「默认中转服务器」这两个默认值对两种界面同样生效。「打开界面时自动体检」不是外观项，它跟着「检测本机环境」这个任务表单里的勾选走，与用哪种界面无关。
  • 圆角大小：统一调整面板、卡片与按钮的圆角，分「利落 / 标准 / 圆润」三档。它改的是圆角令牌本身，不是逐个控件去改；选「材质：扁平」时圆角一律归零 —— 两者冲突时以扁平为准。
  • 侧边栏样式「紧凑」：去掉操作行里的说明行、收紧行距，一屏能多看几项。它只影响侧栏排版，操作的名称、顺序与行为都不变。
  • 说明书也跟着主题走：界面在深色或高对比下打开说明书时，说明书也是深色的（它是一份独立文档，主题由界面带过去）。打印时一律用浅色。

设置页怎么用

设置是顶栏第二个导航项，一页而不是弹窗。页里有三个一级分类，每个分类只装一类信息；维护动作单独一块，集中放在最后。页里出现的每一项都真的会生效 —— 不摆「改了没反应」的开关，也不放还没做的功能占位。

  • 主题外观：主题、强调色、材质、圆角大小、背景光效、背景图片，以及自成一个分组的视觉特效（毛玻璃档位、面板淡入，外加一行「帧率实测」），最后是界面字号、动画效果、侧边栏样式。颜色与排版类改完立刻生效，不需要重启；只有背景图片要等你在大图库里选好那一下。
  • 辅助工具：背景音乐（曲库、播放顺序、循环、音量、播放控制）与填表与日志（记住上次填过的值、清除、日志保留行数、默认游戏端口、默认中转服务器）。这一类是附加项，关掉其中任何一项，联机本身照常工作。
  • 关于与状态：只读信息集中在这里，不重复出现在别处 —— 程序版本、运行环境、数据目录、配置文件路径与写入时间、背景音乐数量、存档合计与隐私说明，加一格四类占用统计（缓存 / 图片 / 音乐 / 配置），再加这份配置的设置变更记录。这一块全部来自程序自己，没有任何编辑入口。若某次启动读配置文件失败，这里会直接说明原因 —— 损坏的内容已被丢弃并回到默认，原文件没有被改写，需要的话可以自己取出来看。
  • 每一项长什么样：标题（右侧可挂一个状态标签）、一行说明、右侧控件，把鼠标停在整行上还能看到更细的解释。「已改动」标签标出与默认值不同的项，一眼看得出自己动过什么；改回默认值它自己就消失。
  • 改完即时落盘：页里没有「保存」按钮，也没有「未保存」这个状态。最近一次写盘的时刻写在窗口最下面的状态栏上（形如「已保存 14:27:04」），保存失败会就地变红。取值不合法时（例如日志行数超范围）不会静默接受，而是回退到默认并当场告诉你哪一项、从什么变成了什么，状态栏同时标出来。
  • 恢复默认只有一个入口，范围在点开之后选：仅主题外观 / 仅辅助工具 / 全部设置。三个范围共用一条就地确认条（不弹系统对话框），确认条里写明影响范围 —— 恢复默认只动设置项，存档里的文件与「记住的填写内容」都不受影响。
  • 其余维护动作（同一块里）：导出全部配置把当前全部设置写成一个带缩进、可读的 JSON 文件，落在存档目录里（文件名形如 mclbx-config-20261009-130738.json），导出后界面上会给出完整路径；导入配置选一份即可，文件里出现本程序不认识的条目时会把不认识的逐条跳过并列出原因，其余照常生效；清空变更记录只清记录；打开数据目录在资源管理器里打开数据目录；复制版本信息把版本号复制到剪贴板；导出诊断包把日志、环境信息与设置打成一个文件，排查问题时比截图准。这些都是「动作」而不是设置项，所以不散落在各分类标题旁边。
  • 导出配置里含中转凭据（如果填过），发给别人之前先自己看一眼。

8 权限与安全

程序默认以管理员身份启动：打开界面时会申请一次权限。原因只有一个——添加 Windows 防火墙入站规则需要管理员权限；先取得权限，这一步就不必再单独弹一次授权框。

  • 提权不会让打洞、自动端口映射或中继更容易成功，这些是普通权限即可完成的协议交互。
  • 拒绝授权、或账户本身不是管理员时，程序照常运行，功能不受影响；只有「入站规则」那一步会再次申请。
  • 关闭默认提权：启动参数加 --no-elevate，或设置环境变量 MCLBX_NO_ELEVATE=1。
  • 入站规则的范围仅限本程序与指定端口，规则名以 mclbx- 开头，可随时用同一操作删除，不影响其它规则与防火墙开关。
  • 本工具有两个入站端口：游戏端口（公网入口）与信令端口 8090（软件入口）。界面上的「放行入站」会一次放行这两个；命令行可用 mclbx firewall --port 25565,8090 一次放行多个。只放行游戏端口的现象是「没装工具的玩家能进、装了工具的反而不行」。
  • 界面服务只监听本机地址，不对局域网或公网开放；页面不与任何外部服务器通信。

首次运行被系统或安全软件拦下

程序没有代码签名，且首次运行会申请一次管理员权限，因此可能被 SmartScreen 或安全软件拦下。这类提示针对的是「未签名程序 + 请求提权」这个组合，并不说明程序本身有问题。遇到时按下面对应一条处理即可：

  • SmartScreen 蓝色窗口（提示「Windows 已保护你的电脑」）：点「更多信息」，核对程序名与文件位置之后点「仍要运行」。程序完全离线运行，不访问任何外部服务器，可以断网验证这一点。
  • 安全软件提示「修改防火墙规则」：来自「入站规则」这一步的正常行为，规则只针对指定端口且限定为本程序。不用公网入口时可以跳过这一步，也就不会有这个提示。
  • 安全软件提示「端口映射 / UPnP」：来自「本机中继」的自动映射探测，可在该项里勾选「不修改路由器端口映射」，检测与联机照常可用。
  • 想先确认它对系统做了什么：单个 exe，不装服务、不写开机启动项；删除文件即可完全清除。数据目录（默认在 exe 同级的 mclbx-data，同级不可写时退到 %LOCALAPPDATA%\mclbx）里只有界面记住的参数、导入的图片与最近一次运行日志，两者都可以用 mclbx forget 与删文件清掉。

9 资源占用

作为常驻后台的工具，本程序在空闲时不产生任何动画帧：界面里没有常驻动画，转圈、闪烁光标这类持续合成新帧的元素一律不用。实测空闲状态 GPU 占用 0.00%、约 1% 单核 CPU。

视觉特效是与这条口径对齐的：毛玻璃只加在几块局部面板上，不铺整页；任务执行期间整体让位，跑完恢复；也不写 will-change（那会为每一块玻璃常驻一个合成层）。实测同一台机器上、界面空闲时，各档毛玻璃的帧率与最慢一帧完全一致（均约 200 帧/秒、最慢 5ms），渲染进程 CPU 也都在噪声级别（整机约 0.01%～0.03%，折算单核 0.3%～0.5%）。觉得偏重时把毛玻璃档位往下调即可。

  • 界面不引用任何外部脚本、样式或在线字体，与程序同在一个 exe 内，可完全离线运行。
  • 网页版界面依赖系统的 WebView2 运行时（Windows 10/11 自带）；若缺失，程序会自动改用系统浏览器打开，功能不变。
  • 内存峰值实测约 390 MB（其中大部分为网页渲染内核）。追求更低占用时可用 --native 启动原生界面。

能传多大

转发这件事本身没有任何上限：没有限速、限流、会话数上限或带宽配额，数据来多少转发多少。内存也不随流量增长 —— 每条连接或隧道占固定大小的收发缓冲区，占用只跟「同时有多少条」有关。

各条路径的软件侧天花板可以在本机用回环量出来（不需要真的大带宽）：在源码目录执行 go test -run '^$' -bench . -benchmem -benchtime 3s .。开发机上的一组参考值：公网入口转发约 350 MB/s（两个方向合计），TCP 中继约 940 MB/s（单向），TCP 兜底通道约 1.2 GB/s（单向），软件入口隧道约 72 MB/s（单向，逐包要过加密与分片，因此低一个数量级）。

这些是软件自己的上限，与线路无关，换更强的 CPU 只会更高；真实链路上还要叠加协议与内核开销，实际会低一些。多玩家就是多条独立连接，能同时吃多个核 —— 一台机器能带多少玩家，取决于它的 CPU 与出口带宽。

自建中继时与本项直接相关的是 --udp-buffer（UDP 收发缓冲区，默认 4 MiB）与 --relay-port-range（把中继端口限在一个段里，防火墙只放这一段）。

10 费用与外部依赖

全部功能都可以免费使用：不需要付费账号、付费服务或付费 SDK。唯一需要自备的是中继所用的那台机器，而自建的三种方式都在本程序里。

功能需要花什么
公网入口、加入房间、断线重连零
环境检测、路况诊断、导出诊断包零
中继转发（房主 / 玩家）、本机中继、TCP 兜底通道一台双方都能访问的机器，自建即可：家里那台有公网地址的电脑就够；程序会先尝试自动端口映射，成功就不必进路由器后台
商用 TURN不必需。中继地址栏语法上兼容任何标准 TURN 服务端，但上面的自建方式已经够用
代码签名不需要。未签名程序首次运行可能被系统或安全软件提示，处理方式见第 8 节

身份绑定：两端各自生成自签证书并交换 SHA-256 指纹，随后在专用流上完成一次挑战-应答校验。
只有校验通过且客户机回执确认后，通道才算建立；任一步失败即断开并说明原因。
绑定完成后两端各显示一个安全码，比对一致即可排除中间人。

SRV 路线：
  房主将「短名称 -> 当前地址与端口」写入 DNS（AAAA 与 SRV 记录）。
  玩家在「直接连接」中输入该短名称即可。
  游戏客户端会查询 _minecraft._tcp.<名字> 的 SRV 记录，获取实际主机与端口，无需填写端口。
  SRV 的目标按 RFC 2782 必须为域名，不能使用 IP 字面量。

程序本体单个可执行文件，无需安装；导入表仅依赖系统库，不附带任何第三方动态库。
运行数据存档目录默认在 exe 同级的 mclbx-data（同级不可写时退到 %LOCALAPPDATA%\mclbx），里面是 config.json、运行日志 gui.log、导入的图片（wallpapers）、背景音乐（music）与缩放缓存（ui-cache）；网页渲染内核数据始终放在 %LOCALAPPDATA%\mclbx，不随存档走。
界面服务默认 127.0.0.1:19870；该端口被占用时自动改用其它端口，不影响功能。
Minecraft 默认端口25565（Java 版）。
本工具的入站端口两个：游戏端口（公网入口）与信令端口 8090（软件入口）；后者可用 --signal 改。防火墙与端口映射要同时覆盖这两个。
界面外观主题、强调色、材质、毛玻璃、背景图片、动效等偏好与「记住的填写内容」存在同一个 config.json（ui 段）里；删掉该文件即全部回到默认。背景图片会被复制一份进 wallpapers，程序另在 ui-cache 下缓存缩放结果（按源文件的修改时间与大小判断是否需要重做，换图时旧的那份会被清掉）。
地址变化开启房间后会每 60 秒比一次公网 IPv6；地址变了（运营商重编前缀、路由器重新拨号、映射换端口）就刷新界面上的地址与邀请文本。已经发出去的那份邀请不会自己更新，需要重新复制。
防火墙规则名mclbx-tcp-<端口> 与 mclbx-udp-<端口>。
